## 3. 当前进度说明

**已完成（M0–M1）**

- 技术路线确定：GPU 为主路径，CPU 作为正确性基线与不支持 Compute 时的回退。
- 6 种构型的坐标、周期、位移全部由 `tools/verify_patterns.py` 独立模拟得出，不是查资料抄的。
- CPU 参考实现完成并通过验证：规则（B3/S23）、环面/死边界语义、快照往返、GPU 行打包转换等价性、6 种构型行为、运行期周期检测器。
- 验证方式见下节；共 71 项检查，0 失败。

**Unity 侧验证结果（已跑通）**

```powershell
& "G:\unity\Editor\Unity.exe" -batchmode -nographics `
  -projectPath "F:\unity_project\My project" `
  -runTests -testPlatform EditMode `
  -testResults "F:\unity_project\My project\TestResults-EditMode.xml"
```

结果：`total=39 passed=39 failed=0 skipped=0`，耗时 0.07 秒。证据文件：`TestResults-EditMode.xml`、`Logs/editmode-tests.log`。

> 命令行注意：`Unity.exe` 是**启动器**，命令会立刻返回（退出码为空），真正的编辑进程在后台跑。必须轮询等待结果文件生成，不能以命令返回作为完成信号。另外编辑器开着时工程被锁，会直接失败。

**验证过程中修正的一个真实错误**

最初手算"3×3 实心块演化后只剩 4 个角"，独立模拟器给出的是 8 个细胞——漏算了紧贴四边的 4 个空位各恰好有 3 个邻居而诞生。这条错误期望值原本会成为一条错误测试，被验证流程拦下了。

**M2 完成情况**

1. `LifePingPong.compute`：`Clear` / `Stamp` / `Step` 三个 kernel，含越界守卫与环面/死边界分支。
2. `GpuGridKernel`：乒乓 RenderTexture、`enableRandomWrite`、Dispatch 与角色交换、同步与异步两种回读。
3. `GridKernelFactory`：能跑 ComputeShader 就走 GPU，否则回退 CPU，控制层无感知。
4. `LifeController` + `LifeDisplay`：启停 / 单步 / 重置 / 切换 6 种构型 / 调速（累加器驱动 + 每帧步数上限）。
5. `GpuParityTests` 5 条用例：6 种构型逐代哈希比对、37×23 非 8 倍数尺寸、死边界撞墙过程、Clear 归零、盖印人口数。
6. 演示场景由代码生成：`Assets/Scenes/LifeDemo.unity`（菜单 `GameOfLife/生成演示场景`，也可命令行重建）。

**M3 完成情况**

1. `StepShared` kernel：16×16 线程组，先把含 1 格 halo 的 18×18 区域载入 `groupshared`，邻居全部从共享内存读。
2. 两条容易踩的坑已处理：屏障必须被全组线程执行（越界线程在屏障**之后**才 return）；halo 的越界按边界语义取对侧或取 0。
3. 档位可配置：`GpuStepMode.Basic` / `SharedMemory`，控制层与工厂都能选，演示场景默认用档一。
4. 一致性测试改为对两种档位各跑一遍（6 种构型、37×23 非 8 倍数尺寸、死边界撞墙）。
5. `StepBenchmarkTests`：4 种网格 × 2 档位，预热 20 代、计时 120 代、重复 3 次取中位数，同时断言两档结果哈希一致。

**M4 完成情况**

1. `StepPacked` kernel：每个线程处理一个 texel 的 4 个细胞，每行 3 次 `float4` Load 覆盖相邻 6 列，邻居读取次数从每 4 细胞 32 次降到 9 次。
2. 盖印改为按 texel 聚合通道掩码后写入，避免同一 texel 的读改写竞争（横向音符的三个细胞会落在同一 texel 的三个通道上）。
3. 明确并强制了适用前提：网格宽度必须是 4 的倍数；不满足时工厂自动降级到档一，而不是给出错误结果。
4. 一致性测试扩到三档；基准也覆盖三档并断言终态哈希一致。
5. 过程中被测试抓出两个真实 bug（纹理用错尺寸、死值 alpha 写成 1 导致整片棋盘凭空有生命）与一个算法错误（把自己算成邻居），详见实现文档 §5.5。

**M5 完成情况**

1. `StepBitPacked` kernel：`RWTexture2D<uint>` 承载状态，每个线程处理 32 个细胞；邻居统计走位并行——每行算左/中/右掩码，再用全加器压成 2 位计数，最后把三行相加。
2. 跨字边界按"左移补上一个字的最高位、右移补下一个字的最低位"处理，首尾字在环面模式下互相补位。
3. `ExpandBitPacked` 展开 kernel：位打包纹理不能直接显示，按需（每代最多一次）展开成 1 texel = 1 细胞供显示与回读。
4. 明确适用前提：网格宽度必须是 32 的倍数；不满足时工厂降级到档二/档一。
5. 一致性测试扩到四档；基准覆盖四档并断言终态哈希一致。
6. 档三的价值被数据澄清：**显存降 32 倍，速度只快 1.10~1.23 倍**。它是四档中最快的，但性价比不如档二，因此演示默认仍用档二。

**M6 完成情况**

1. GPU 内核埋点：`Step` / `Expand` / `Readback` 三个热点用 `ProfilerMarker` 标记，可长期留在代码里，Profiler 里直接可见。
2. 基准增加 CPU 提交耗时口径（`ProfilerRecorder`），与墙钟时间对照，回答"瓶颈在提交侧还是执行侧"。
3. **回归门槛**：基准用例同时断言"四档终态哈希一致"与"任何一档不超过基础版的 1.15 倍耗时"。四档同轮测量，用相对比值做门槛，避免绝对耗时带来的假失败。
4. 技术分析新增 §6.3 选型建议（四档分别适用什么场景），并补上"为什么档二/档三有宽度约束"的说明。
5. 得到一条量化结论：CPU 提交约 2.4 µs/代、与档位和尺寸几乎无关，因此**优化收益全部来自 GPU 侧**；256² 上提交占 24%，这正是小网格加速比被稀释的原因。

**M7 完成情况**

1. 自定义 Inspector（`LifeControllerEditor`）：构型下拉（带分类/尺寸/细胞数/周期/位移摘要）、播放/暂停、单步、重置、下一个构型、重新分析、调速、换档位、网格尺寸与边界；配置一变就重建内核。
2. **构型分析读数**：`AnalyzeCurrentPattern()` 把当前状态取回 CPU 参考实现向前演化，用与测试相同的判定逻辑算出周期与每周期位移，并标注是否与构型声明一致。
3. 重置后自动分析，因此"当前是稳定静物 / 振荡器 / 飞船，周期几、每周期位移多少"是屏幕上直接可读的数字，而不是靠盯着画面看。
4. 快捷键（空格切换播放、N 下一个构型、R 重置、→ 单步）。项目是**新版 Input System only**（`activeInputHandler = 1`），旧版 `UnityEngine.Input` 会直接抛异常，因此走 Input System API 并保留空引用守卫。
5. 菜单项 `GameOfLife/打开演示场景`，场景缺失时自动先生成。

**M8 完成情况**

1. 新增工程根目录 `README.md`：怎么跑、怎么看效果、怎么调整、怎么检验（含预期输出），以及构型表、四档性能表、选型建议、目录结构与已知约束。
2. 技术分析补 §8 结论（把 5 条主要结论集中列出），风险表增加"结果"列，标注每条风险的最终状态。
3. 通读两份文档，清理过时的档位数与"待补"标记。

**全部里程碑完成**

61 条 Edit Mode 测试通过（含 4 档 GPU 一致性、性能回归门槛）；独立模拟器与独立 .NET 验证器均可复跑。

## 4. 工作流约定

**验证优先**：任何"我认为应该如此"的期望值，都要先被独立工具或参考实现确认，再写进断言。M1 已经证明这一步不是形式主义。

| 验证层 | 工具 | 命令 | 适用 |
|---|---|---|---|
| 构型数据 | Python 独立模拟器 | `python tools/verify_patterns.py` | 坐标、周期、位移 |
| 核心逻辑 | Edit Mode 测试 | `Unity -batchmode -runTests -testPlatform EditMode` | 规则、边界、快照、构型行为 |
| GPU 一致性 | `GpuParityTests` | 同 Edit Mode，但**不能加 `-nographics`** | GPU 与 CPU 哈希一致 |
| 性能 | `StepBenchmarkTests`（自动 + `ProfilerMarker`） | 同 Edit Mode（需图形设备） | 四档的实际收益与回归门槛 |

**注意**：Unity 命令行跑测试要求工程未被编辑器占用。编辑器开着时 `-runTests` 会直接以退出码 1 结束。

**编码约定**

- `Assets/Scripts/Runtime/Core/` 内的代码**不引用 UnityEngine**，保证可脱离引擎单元测试。
- 构型数据只放在 `PatternLibrary`，UI 与盖印逻辑都从它读取，不各自硬编码坐标。
- GPU 与 CPU 实现共用 `IGridKernel` 契约，比对通过 `GridSnapshot` 进行。

## 5. 风险与对策

| 风险 | 影响 | 对策 | 状态 |
|---|---|---|---|
| ComputeShader 在目标平台不可用 | 演示直接失败 | `GridKernelFactory` 按 `SystemInfo.supportsComputeShaders` 回退 CPU | ✅ 已实现 |
| 纹理读写方向（Y 轴）不一致 | 图案镜像、飞船反向 | kernel 约定 texel(x,y) 与网格(x,y) 一一对应，回读哈希比对已在计算侧排除翻转 | ✅ 计算侧已排除；显示端留 `FlipY` 开关待人工确认一次 |
| 位打包跨字边界写错 | 档三结果错误且难以察觉 | 档三必须与档一逐代哈希比对，不能只看画面 | 待验证 |
| 演进步长与帧率耦合 | 高速档卡死主线程 | 累加器驱动 + 每帧步数上限 | 待实现 |
